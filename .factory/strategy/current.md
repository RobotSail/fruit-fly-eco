### Anti-patterns to Avoid
- **Never call `policy`/`_lif`/`LIFNetwork` from a FastAPI handler or async task** — silent training data corruption via shared mutable tensor state (`V`, `refractory`, `spike_counts`). The GIL does NOT prevent semantic races on PyTorch in-place ops. All neural sampling must be sequential with training inside `_training_loop`.
- **Never animate SVG filter attributes (`stdDeviation`, `feColorMatrix values`) in `@keyframes`** — forces main-thread repaint every frame, fighting the project's compositor-friendly design principle. Animate only `opacity` and `transform` on pre-filtered elements.
- **Never send raw per-neuron arrays over `/api/neural`** — at 200 neurons it's fine, but at 166K it's 3MB per poll. Always send layer-aggregated means (5 scalars). Build this constraint in from day one.
- **Don't fix the FCI bug** (`kc_mean_rate` is actually `mean_reward * 10`) — out of scope, requires recalibrating thresholds across `compute_fci()` and `_resolve_body_color()`. Instead, create a new, honestly-named `neural_activity` signal for the glow effect, completely independent of FCI.
- **Don't introduce a second lock** — extend the existing `_metrics_lock`-guarded dict with new keys; contention is negligible at this update rate.
- **Don't modify fixed surfaces** — `LIFNetwork.step()`/`simulate()`, `PPOTrainer.update()`/`collect_rollouts()`, `EconomyMDP`/`solver.py`, `eval/score.py` are all off-limits.
- **Don't add external `<script src=...>` references** — all JS must be inlined in the f-string HTML template (factory guard: single self-contained HTML).
